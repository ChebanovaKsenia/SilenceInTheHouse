# ЧАСТЬ 1. ТЕОРИЯ: Корпоративные информационные системы (КИС)

## 1.1. Понятие «Корпоративные информационные системы»

**Корпоративная информационная система (КИС)** — это комплекс программных, технических, информационных и организационных средств, объединённых в единую систему для сбора, хранения, обработки, передачи и представления информации, необходимой для управления бизнес-процессами на всех уровнях организации.

КИС — это не просто «база данных» или «сайт», а **единая экосистема**, которая связывает между собой отделы компании (бухгалтерию, склад, продажи, HR, производство) и обеспечивает руководителей актуальной информацией для принятия решений.

**Основные классы КИС:**
- **ERP** (Enterprise Resource Planning) — управление ресурсами предприятия (SAP, 1С:Предприятие)
- **CRM** (Customer Relationship Management) — управление взаимоотношениями с клиентами (Salesforce, Bitrix24)
- **SCM** (Supply Chain Management) — управление цепями поставок
- **HRM** (Human Resource Management) — управление персоналом
- **MES** (Manufacturing Execution System) — управление производством

## 1.2. Требования, предъявляемые к КИС

Требования к КИС делятся на **функциональные** (что система должна делать) и **нефункциональные** (как она должна это делать).

| Категория | Требования | Пример |
|-----------|-----------|--------|
| **Функциональные** | Автоматизация бизнес-процессов, формирование отчётов, интеграция с внешними системами, разграничение прав доступа | Модуль «Склад» автоматически списывает товар при продаже |
| **Надёжность** | Работа 24/7, резервное копирование, восстановление после сбоев | Время восстановления после аварии ≤ 4 часов |
| **Производительность** | Время отклика ≤ 2 сек, поддержка 1000+ одновременных пользователей | Отчёт формируется не дольше 5 секунд |
| **Масштабируемость** | Возможность добавлять модули и пользователей без перестройки архитектуры | Добавление нового филиала без изменения кода |
| **Безопасность** | Шифрование данных, аутентификация, защита от SQL-инъекций и XSS | Ролевая модель доступа, двухфакторная аутентификация |
| **Эргономичность** | Интуитивный интерфейс, минимальное время обучения сотрудников | Новый сотрудник осваивает систему за 1-2 дня |
| **Сопровождаемость** | Чистый код, документация, возможность обновлений без остановки работы | Обновление в ночное время без простоя |
| **Интегрируемость** | Поддержка API (REST, SOAP), обмен данными с другими системами | Интеграция с банком для онлайн-платежей |

## 2.2. Аудит технического долга (Реестр «костылей»)

Технический долг — это временные решения, которые работают сейчас, но могут создать проблемы в будущем.

| № | Описание «костыля» | Риск | Приоритет | План действий |
|---|---|---|---|---|
| 1 | Поиск игрока через `GameObject.FindGameObjectWithTag("Player")` в `Start()` нескольких скриптов (Bed, TeddyBear, InteractionHint) | **Средний** — замедляет старт сцены, ломается при смене тега | **Исправить сейчас** | Заменить на прямые ссылки через `[SerializeField]` или единый `GameManager` |
| 2 | Хардкод текстовых строк в `Debug.Log` и UI-подсказках | **Низкий** — затруднит будущую локализацию на другие языки | Переписать позже | Вынести все строки в `ScriptableObject` или систему локализации |
| 3 | ИИ монстра реализован через `switch` в `Update()`, а не через паттерн State | **Средний** — при добавлении состояний («поиск по звуку») код станет нечитаемым | **Принять как риск** | Переписать на полноценный State Pattern перед масштабированием |
| 4 | Видео кат-сцен загружаются как обычные `Video Clip` без асинхронной подгрузки | **Низкий** — возможны микро-фризы при первом воспроизведении | Переписать позже | Реализовать `Preload` видео при загрузке сцены |
| 5 | Использование `Invoke(nameof(...), 2f)` для задержек вместо корутин | **Низкий** — сложно отлаживать и отменять вызовы | Переписать позже | Заменить на `Coroutine` с `yield return new WaitForSeconds` |
| 6 | `AudioListener.volume` для SFX вместо полноценного микширования | **Средний** — влияет на все звуки сразу, нельзя регулировать отдельно | **Исправить сейчас** | Все звуки перевести на группы `AudioMixer` (SFX, Music, Ambient) — **ВЫПОЛНЕНО в v0.4.0** |
| 7 | Жёсткая привязка длительности видео (`videoDuration = 7.019f`) | **Средний** — при замене видео нужно править код | **Исправить сейчас** | Читать длительность из `videoPlayer.clip.length` |

## 2.3. Стратегия тестирования

### 2.3.1. Подходы и уровни тестирования

| Уровень | Что тестируем | Инструмент | Периодичность |
|---------|--------------|-----------|---------------|
| **Модульное (Unit)** | Отдельные методы: расчёт дистанции, логика квеста, сохранение в `PlayerPrefs` | NUnit / ручной вызов | При изменении логики |
| **Интеграционное** | Взаимодействие систем: подбор мишки → ярость монстра → остановка при победе | Ручное тестирование в Unity | После каждой новой фичи |
| **Системное (E2E)** | Полный игровой цикл: меню → кат-сцена → квест → победа/поражение | Ручное тестирование | Перед каждым релизом |
| **Smoke-тест** | Критический путь: игра запускается, игрок ходит, монстр не вылетает | Ручное, 2 минуты | Перед каждым коммитом |
| **Регрессионное** | Проверка, что старые фичи не сломались после новых изменений | Чек-лист | После крупных изменений |

### 2.3.2. Критерии тестирования

**Критерии начала тестирования:**
- Проект компилируется без ошибок (Error) в консоли Unity
- Базовая сцена `MainMenuScene` загружается
- FPS ≥ 30 в течение 30 секунд
- Отсутствуют критические предупреждения (Warning) в консоли

**Критерии окончания тестирования:**
- Все пункты чек-листа ручного тестирования пройдены
- Дефекты с приоритетом High/Critical устранены
- Игра стабильно работает 15+ минут без утечек памяти
- FPS не падает ниже 30 в течение всего тестирования

### 2.3.3. Чек-лист ручного тестирования (Core Loop)

#### Главное меню и настройки
- [ ] Кнопка «Играть» запускает сцену с плавным затемнением
- [ ] Кнопка «Настройки» открывает панель настроек, скрывая кнопки меню
- [ ] Кнопка «Выход» вызывает панель подтверждения «Да / Нет»
- [ ] Панель подтверждения появляется **поверх** кнопок меню
- [ ] При открытой панели подтверждения нельзя навестись на кнопки под ней (Raycast Target работает)
- [ ] Кнопка «Да» закрывает игру (в редакторе — останавливает Play Mode)
- [ ] Кнопка «Нет» возвращает в главное меню
- [ ] **Курсор разблокирован и виден** при загрузке главного меню

#### Настройки
- [ ] Выбор разрешения (5 вариантов) сохраняется и применяется после «Сохранить»
- [ ] Выбор режима экрана (Оконный / Полноэкранный / Без рамки) применяется
- [ ] Ползунок «Музыка» меняет громкость фоновой мелодии в реальном времени
- [ ] Ползунок «Звук» меняет громкость видео и эффектов в реальном времени
- [ ] Кнопка «Сбросить» возвращает настройки к значениям по умолчанию
- [ ] Кнопка «Назад» закрывает панель настроек

#### Игровой процесс
- [ ] Кат-сцена пробуждения проигрывается после загрузки уровня
- [ ] Звук кат-сцены регулируется ползунком «Звук» в настройках
- [ ] Подход к кровати без мишки + нажатие E → сообщение «Нужно сначала взять мишку»
- [ ] Подбор мишки (E) → монстр переходит в режим погони (ускоряется)
- [ ] Возвращение к кровати с мишкой + нажатие E → монстр мгновенно останавливается
- [ ] Мишка кладётся на кровать, квест отмечается как выполненный
- [ ] **Победа:** затемнение → видео завершения (7 сек) → музыка плавно появляется → возврат в меню
- [ ] **Поражение:** касание монстра → видео смерти → перезагрузка сцены

#### Аудио
- [ ] Гитарная мелодия играет в главном меню (зациклена)
- [ ] При нажатии «Играть» музыка плавно затихает (1.5 сек)
- [ ] После победы музыка плавно появляется во время видео (3 сек)
- [ ] После возврата в меню музыка продолжает играть
