# Тихий Дом (SilenceInTheHouse)

## 1. О проекте

**«Тихий Дом» (SilenceInTheHouse)** — трёхмерная хоррор-игра от первого лица, разрабатываемая на Unity.

Игрок управляет девочкой Мелиссой, которая оказывается в опасном месте и должна исследовать окружение, взаимодействовать с предметами и избегать столкновения с существом, представляющим угрозу.

Основное внимание уделяется исследованию локаций, игровому взаимодействию, атмосферному звуковому сопровождению и элементам психологического хоррора.

## 2. Жанр и особенности

- Жанр: хоррор, приключение, исследование.
- Платформа: Windows PC.
- Движок: Unity.
- Перспектива: от первого лица.
- Основные механики:
  - перемещение и исследование окружения;
  - взаимодействие с предметами;
  - подбор предметов;
  - поведение монстра, реагирующего на действия игрока;
  - экранные эффекты, звуковые события и сцены завершения уровня.

## 3. Технологии

- Unity — игровой движок.
- C# — реализация игровой логики.
- Git и GitHub — контроль версий и хранение истории разработки.
- Unity UI — интерфейс главного меню и настроек.

## 4. Структура проекта

Основные каталоги Unity-проекта:

- `Assets/` — игровые сцены, скрипты, модели, материалы, текстуры, аудио и другие ресурсы.
- `Packages/` — зависимости и пакеты Unity.
- `ProjectSettings/` — настройки проекта и параметры сборки.

## 5. Запуск проекта

1. Установить совместимую версию Unity через Unity Hub.
2. Открыть проект через Unity Hub, выбрав его корневую папку.
3. Дождаться импорта ресурсов и завершения компиляции скриптов.
4. Открыть сцену главного меню.
5. Запустить игру кнопкой Play в редакторе Unity.

Для запуска готовой версии на Windows следует использовать исполняемый файл сборки игры.

## 6. Управление

Точные клавиши необходимо сверять с актуальной реализацией контроллера игрока.

Основные действия включают:
- перемещение по локации;
- взаимодействие с игровыми объектами;
- подбор предметов;
- бег.
## 7. Главное меню и настройки

Главное меню предоставляет доступ к запуску игры, настройкам и выходу.

В настройках предусмотрены:
- выбор разрешения экрана;
- выбор режима отображения;
- регулировка громкости с отображением значения в процентах;
- автосохранение настроек;
- сброс настроек до значений по умолчанию;
- возврат в главное меню.

Настройки сохраняются между запусками с использованием PlayerPrefs.

## 8. Журналирование событий

Для диагностики и проверки игровой логики используется система логирования Unity (`Debug.Log`, `Debug.LogWarning`, `Debug.LogError`).

Логи предназначены для фиксации важных событий, например:
- запуска игры и переходов между меню;
- изменения и сохранения настроек;
- взаимодействия с игровыми предметами;
- ключевых состояний противника;
- завершения игровых этапов;
- ошибок, связанных с отсутствующими объектами или ресурсами.

Сообщения доступны в окне Console редактора Unity. В окончательной сборке следует отдельно проверить, какие диагностические сообщения необходимо оставить.

## 9. Стратегия тестирования

Проверка проекта проводится вручную в Unity Editor и, по возможности, в собранной Windows-версии.

### Основные проверки

- запуск игры из главного меню;
- переход в настройки и возврат обратно;
- регулировка громкости и проверка отображения процентов;
- выбор разрешения и режима экрана;
- сохранение и сброс настроек;
- подбор предметов;
- проверка поведения противника;
- корректность переходов между сценами;
- проверка Console на ошибки и предупреждения;
- проверка производительности на целевом компьютере.

Результаты тестирования следует фиксировать отдельно: дата, версия сборки, условия проверки, ожидаемый результат, фактический результат и обнаруженные дефекты.

## 10. Совместимость

Целевая платформа проекта — Windows PC.

Основная среда разработки — Unity 2023.3.62f3.

Совместимость необходимо проверять на фактических конфигурациях оборудования, версиях Windows, разрешениях экрана и графических настройках. Поддержка конкретных конфигураций считается подтверждённой только после тестирования.

## 11. Технический долг

При дальнейшей разработке необходимо контролировать:
- корректность ссылок между объектами и компонентами;
- дублирование логики в скриптах;
- обработку ошибок и отсутствующих ресурсов;
- производительность игровых механик;
- согласованность документации с текущей реализацией;
- отсутствие временных и неиспользуемых ресурсов в репозитории.

Выявленные проблемы следует фиксировать с указанием влияния на проект и приоритета исправления.

## 12. Контроль версий и журнал изменений

Исходный код проекта хранится в GitHub. Изменения рекомендуется фиксировать отдельными коммитами с понятными сообщениями.

История изменений проекта ведётся в файле `CHANGELOG.md`.

## 13. Статус проекта

Проект находится в разработке. Состав игровых механик, содержание уровней, совместимость и результаты тестирования уточняются по мере реализации и проверки новых версий.
